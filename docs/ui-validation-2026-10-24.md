# FanController UI 验证记录

日期：2026-10-24。版本：0.4.6 preview。本文记录 UI 改动及其验证范围。

## 实际修改

- 保留 React、Ant Design、C# WPF/WebView2、产品名和已确认图标。`app/theme.ts` 统一语义配色、36 px 控件、8/12 px 圆角、字体、菜单和选中状态；显式设置状态语义底色，避免主题算法派生出对比不足的标签。
- 新增浅色、深色、跟随系统三种选择，首次跟随系统，沿用原主题持久化键。首屏脚本、React、原生底色和托盘同步选择；原生镜像主题与关闭偏好供下次启动使用。演示和 QA 不写这些生产镜像。
- 名称和图标集中在 40 px 标题栏。侧栏改为 224/56 px，可显式展开/折叠并保存选择；设置固定在底部，风扇设置保留业务入口。
- 设备列表在窄窗口保留操作，表格在自身区域横向滚动，长设备名允许换行。曲线按实际宽度计算坐标并保持 12 px 刻度；趋势图不跨缺失读数连线，修正范围钳制。
- `NumberInput` 保留组件库数值与键盘行为，只补齐数值增减按钮的中文可访问名称。各单组表单补标签、禁用与忙碌状态。
- 方案和单组编辑共用草稿关闭确认；真正退出同样检查草稿。错误通知持续保留，连接故障在内容区提供重连操作。
- 最小化保留任务栏窗口，关闭按保存的“托盘/退出”选择执行；显式退出继续等待风扇恢复和服务退出，失败保留应用。WebView2 原生拖动区域支持标题栏移动、双击和系统菜单，旧运行库保留桥接回退。最大化时补偿系统隐藏边框。
- 修复减少动效下的浮层定位：原规则给所有元素设置非零过渡，连同步位置测量也被延迟。改为零时长过渡，并同步 Ant Design 的 motion token。
- 首次创建并连接服务不再被误报为重新启动；既有服务的恢复和用户重连仍按重启结果反馈。

## 验证边界

- 离屏 WebView 浮层用例未能可靠展开菜单，已移除，不能把它当成实际键盘交互证据。减少动效定位在前台浏览器验证；真实原生 Select 另以鼠标验证展开与选取。移除失真用例后，已重建并跑通完整桌面回归。之前的失败诊断保留在 `artifacts/tests/desktop-offscreen-popup-previous-error.txt`，当前运行没有生成 `desktop-ui.png.error.txt`。
- 当前真实原生验证只有 200% DPI；100%、125%、150%、跨显示器缩放和负坐标屏幕没有实测。浏览器等效宽度检查不代表这些原生 DPI 场景。
- 真实设备写入及物理风扇退出恢复未验证。本次保留真实设备状态，仅验证模拟端口。
- Windows 安装程序和便携 ZIP 按同一版本构建并提供 SHA-256。安装器退出顺序在隔离模拟程序中验证；没有对日常安装执行安装、升级或卸载，也没有覆盖用户风扇配置。

发布包的校验值随 Release 中对应的 `.sha256` 文件提供；本地检查报告位于 `artifacts/tests`。

如需再次独立预览，可运行：

```powershell
& './artifacts/app/FanController.exe' --ui-qa
```

该入口使用模拟风扇、内存配置和独立缓存；查看后从设置正常退出。

## 共用规范建议

现有主题、控件与生命周期规范足够指导本项目，不扩写同义规则。建议补充一个具体校验点：减少动效不能给原本没有过渡的浮层定位属性引入非零过渡；在该模式下量取菜单真实矩形，确认它位于视口内，而不只检查“已展开”的可访问状态。
