# 风扇调节方案

日常使用先保证散热，再尽量保持安静。低负载时无需追求最低温度，持续负载升高时应逐步提速。FanController 的曲线是初调起点，不能替代风扇型号、散热器、机箱风道和室温的实际检查。

## RPM 与输出百分比

没有适用于所有风扇的固定 RPM。常见 120 / 140 mm 机箱风扇可以先在实测约 700–900 RPM、塔式 CPU 散热风扇在约 700–1100 RPM 附近试听。这是低负载时的工程初调范围，不是厂商规定，也不保证所有型号都能达到。标称最低转速更高时，以该型号规格和稳定运转情况为准；小尺寸风扇、冷排风扇和水泵不能直接套用。

软件写入的是输出百分比，RPM 来自转速传感器。当前版本没有自动转速标定，也不提供目标 RPM 闭环控制。不能把“30%”直接当成“最高转速的 30%”。[Noctua NA-FC1 手册](https://cdn.noctua.at/media/noctua_na_fc1_manual_en.pdf) 说明，PWM 输入与转速的对应关系会因风扇而异，未必线性。

先确认主板使用正确的 PWM / DC 模式，并找出风扇能稳定启动和持续运转的最低输出，再调整曲线。最低输出默认 30%，只表示尚未标定的起点；已保存的最低值会保留，不能把默认值当成硬件保证。[Noctua 调节指南](https://www.noctua.at/en/support/faqs/how-do-i-optimise-my-fan-settings) 同样建议按具体风扇确认最低转速，并避免把通用曲线当成最终设置。

## 编辑、预览与应用

1. 在概览点击“配置与预览”，按实际接线确认风扇用途。`Fan #1` 等名称无法说明接了什么，默认不勾选；已识别的水泵保留原设置。
2. 勾选参与调节的风扇，逐组修改温度来源、最低输出、响应平滑和曲线。已有曲线与固定输出会保留；“使用安静起点”只修改当前草稿。
3. 点击“预览应用内容”，核对每组名称、通道、完整曲线、温度来源和参数。预览同时列出要恢复及保留原设置的风扇。
4. 点击“应用方案”后才写入硬件。未勾选但正在接管的风扇会恢复原设置；未接管的风扇保留当前设置，仅保存用途和排除状态。

编辑和预览期间，风扇继续使用当前设置。遥测刷新不会重置草稿。服务会在首次写入前检查全部通道、参数和必要温度，任一校验失败都不执行这批设置。设备写入仍可能部分失败；界面会报告失败项，并显示实际仍在调节的风扇。保存失败会保留草稿，当前运行参数由服务单独发布，不能拿磁盘上的旧配置冒充已生效参数。

## 安静起点的具体参数

以下值由应用提供，用户可以修改；它们不是厂商认证曲线，也不对应某个固定 RPM。

| 用途 | 默认温度来源 | 曲线节点（温度 → 输出） | 升温 / 降温平滑 |
| --- | --- | --- | --- |
| CPU 风冷散热风扇 | CPU 最高有效温度 | 30°C → 40%；50°C → 40%；65°C → 55%；75°C → 75%；85°C → 100% | 3 秒 / 20 秒 |
| 机箱风扇 | CPU、GPU 都可用时取较高温度，否则取 CPU | 30°C → 30%；55°C → 30%；65°C → 45%；75°C → 65%；85°C → 100% | 5 秒 / 30 秒 |
| 显卡风扇 | 默认保留原设置 | 用户明确选择接管时：30°C → 35%；50°C → 35%；60°C → 45%；70°C → 65%；80°C → 100% | 接管时 2 秒 / 15 秒 |
| 未确认通道、水泵 | 保留原设置 | 不自动接管 | — |

输出取曲线值与最低输出中的较大值，并受硬件范围限制。节点之间线性插值，预览显示最低值限制后的有效曲线。例如最低输出 45% 时，30°C → 30% 实际按 45% 处理。

显卡默认保留驱动设置。[AMD 的调节说明](https://www.amd.com/en/resources/support-articles/faqs/DH3-020.html) 指出，支持 Zero RPM 的显卡可在低负载时停转，负载和温度升高后再启动。软件接管后会保持最低输出，因此界面会提醒：需要保留停转时，应取消勾选显卡。具体功能仍取决于显卡和驱动。

## 平滑与保护

持续升温应增加散热，瞬时波动则不必立刻让风扇大幅变速。[ASUS Fan Xpert 说明](https://www.asus.com/support/faq/1034000/) 也提供升速、降速时间设置，以减少短时间内的大幅变化。应用采用独立的升温与降温平滑，默认时间是本项目的选择。

平滑秒数是指数滤波的时间常数，不是等待时间。温度开始变化时就逐步响应；一个时间常数后约完成 63% 的温差变化，持续约三个时间常数后接近 95%。设为 0 秒时直接使用当前温度。输出下降每秒最多 3 个百分点。旧配置没有平滑字段时继续使用旧版的 3°C 回落滞回；在编辑器中预览并应用后，按明确列出的平滑参数执行。

保护使用未经平滑的最新温度。CPU 达到 90°C、GPU 非热点温度达到 90°C、热点达到 105°C，或必要温度缺失、失效时，已接管风扇立即请求最高输出。曲线末节点设为 100% 时，原始温度达到该节点也会立即全速。未接管风扇继续由硬件或驱动管理。这些是软件兜底阈值，不代表所有型号的最高工作温度；使用前仍需核对硬件厂商规格。

退出、恢复原设置和安装升级继续走原有的设备恢复流程。启动应用不会自动接管风扇。新版本保留配置文件位置和通道 ID，角色和平滑参数是兼容旧配置的可选字段；原配置无法读取时保留文件并停止覆盖。

## 验证范围

规则、参数传输、缺失温度、平滑、保护和恢复使用模拟端口验证。原生 WebView2 流程检查了草稿、预览、应用、当前参数、排除状态及深浅主题。浏览器还检查了 900 像素宽度、未知通道和水泵。测试没有写入真实风扇，也没有测量实际噪声；合适的最低输出和日常 RPM 仍需在具体机器上确认。
